# Passenger deployment preparation

The observed ServerNet account has Python 3.12.16, Node and Passenger, without Docker. `passenger_wsgi.py` provides a WSGI entry point for the existing HTTP/SSE service using pinned a2wsgi. It starts/stops FastAPI's lifespan on a dedicated event loop and closes its HTTP client on worker shutdown. The adapter is tested in memory; real Passenger/Apache/Cloudflare behavior is not yet accepted.

1. Use the published and reviewed Studio commit, outside `public_html`, with only the `servernet/` customer application. Do not expose upstream local tools, source, private configuration or the SQLite database through a document root. Preserve any existing files and registered applications.
2. Create a private Python 3.12 virtual environment and install `servernet/hosted/requirements.txt`. Build the customer web app with its committed lockfile and Node 24. The Python entry point is `servernet/passenger_wsgi.py` and the application callable is `application`.
3. Register a dedicated application for the **verified** Studio domain in cPanel Application Manager. Its application root is the private `servernet/` directory, not the Laravel console or main site's webroot. Set Passenger's Python interpreter to that virtual environment. Check the generated application/vhost mapping before activation; never replace another application's settings.
4. Configure the same private client secret in Laravel and the Studio backend. Store a separate, persistent Fernet encryption key for Studio sessions. Use the environment keys from `servernet/.env.example`; set the fonts directory to the existing IRANSans font files and the database to a private runtime directory (directory mode 0700, database 0600). The source URL must identify the exact published source commit. Keep all these values out of source, logs, terminal output and frontend builds.
5. Stage the narrowly reviewed core files with expected-before hashes and private backups. Apply only the new Studio grant migration and explicitly scoped cache/OPcache steps. Keep the SSO/download feature off until private acceptance. Do not run unrelated migrations, queues, cron or model calls as health checks.
6. Verify `/healthz`, HTML/static fonts, no cache of private responses, console callback, cookie security, Google/account/registration/2FA returns, two-customer isolation and logout. Verify SSE delivery over the actual HTTPS proxy, including disconnect/unknown billing behavior. No WebSocket support is claimed by this WSGI deployment.
7. Financial end-to-end acceptance requires an authorized test account and spending cap. Check actual Gateway usage and wallet ledger once; do not retry an unknown billable outcome. Only after acceptance should the public downloads feature, signed installers and update feed be published together.

## Private configuration on Passenger

If Application Manager cannot supply environment variables, copy the **template** `servernet/config.example.json` into the private application's `servernet/runtime/config.json`, outside every document root. This directory is ignored by Git. The template contains placeholders, never usable credentials. Create the runtime directory with mode 0700 and the actual file with mode 0600 (0400 is also accepted), owned by the same user that runs Passenger. The file and its containing path must not use symlinks; hard-linked files are rejected. Protect its backups in the same way.

The loader accepts the six settings in the template and the optional Gmail settings below. It cannot change Gateway/console endpoints or enable testing mode. Reads are limited to 16 KiB. Malformed JSON, duplicate/unknown fields, empty or invalid values, shared permissions and a different POSIX owner stop startup without including values or paths in the error.

An environment value overrides the matching file value. Invalid file fields are rejected before overrides, and an empty environment override is an error. If the default file is absent, environment-only deployments continue to work. To use another **absolute, private** path, set `SERVERNET_STUDIO_CONFIG`; a missing explicitly configured file is an error, even if environment settings exist. No secrets are copied into `os.environ`. Ordinary `.env` files are not automatically loaded by the Python entry point; Docker Compose's `env_file` remains supported.

Set `SERVERNET_STUDIO_FONTS` to the existing site's three IRANSans WOFF2 files, `SERVERNET_STUDIO_DB` to persistent private storage and `SERVERNET_STUDIO_SOURCE_URL` to the exact deployed public commit. Keep the encryption key stable across application updates; replacing it would prevent existing sessions/flows from decrypting. This loader never creates or rotates credentials. Restart only this Passenger application after a reviewed configuration change.

### Optional Gmail connection

Gmail requires its own Google Web application OAuth client and an enabled Gmail API in the same Google Cloud project. Register `https://studio.servernet.cloud/auth/connectors/gmail/callback` as an authorized redirect URI and configure the consent screen for `https://www.googleapis.com/auth/gmail.labels`. Google lists this scope as non-sensitive and includes label editing in its grant. Studio uses it only for the inbox unread count. Follow the applicable [Google OAuth verification requirements](https://developers.google.com/workspace/gmail/api/auth/scopes) before enabling the OAuth app for the intended audience.

Set `SERVERNET_STUDIO_GMAIL_CLIENT_ID` and `SERVERNET_STUDIO_GMAIL_CLIENT_SECRET` together in the private configuration or environment. Leave both unset until the provider setup is ready. Connect and disconnect using an authorized test account before enabling for customers. Verify Google consent, unread inbox count and revocation across two distinct Studio accounts. The connector requests only the inbox unread count, stores the encrypted refresh token and performs no background mailbox requests.
